# SoilWise Dissemination & Guidelines

A Python-based [MkDocs](https://www.mkdocs.org/) documentation site for the SoilWise Dissemination & Guidelines and User Manual (Deliverable D4.6).

The published site is available at: **https://soilwise-he.github.io/prototype-dissemination-guidelines/**

---

## Repository structure

| File / folder | Purpose |
|---|---|
| `docs/` | MkDocs source pages, images, and custom CSS |
| `docs/04-Deliverables/` | Folder-based Deliverables section with an overview page and child deliverable pages |
| `docs/05-Guides/` | Knowledge pages generated from source PDFs and reviewed summaries |
| `mkdocs.yml` | MkDocs configuration (theme, plugins, build settings) |
| `docs/.pages` | Folder-local navigation order for top-level site pages |
| `docs/04-Deliverables/.pages` | Deliverables section label and local ordering |
| `pdf-to-images/` | PDF intake workflow: drop PDFs, render page images, extract text, create docs pages |
| `pyproject.toml` | Python project metadata and dependencies managed by `uv` |
| `site/` | Built site output (generated by MkDocs) |

## Building the site locally

### Prerequisites

- [Python](https://www.python.org/) >= 3.10
- [`uv`](https://docs.astral.sh/uv/)

Install dependencies:

```bash
uv sync
```

### Run local preview server

```bash
uv run mkdocs serve
```

Open `http://127.0.0.1:8000/` in your browser.

### Build static site

```bash
uv run mkdocs build
```

The built site is placed in the `site/` folder.

### Ingest a PDF into the Guides section

1. Save one or more PDF files into `pdf-to-images/inbox/`.
2. Run the processor:

```bash
uv run python pdf-to-images/process_inbox.py
```

This same command is the intended entrypoint for local runs and for GitHub Actions.

The workflow will:

- render each PDF page to PNG images;
- extract page text into a sidecar text file;
- create a new page under `docs/05-Guides/`;
- move the source PDF to `pdf-to-images/archive/`;
- move failed files to `pdf-to-images/rejected/`.

## Publishing to GitHub Pages

This repository is configured to publish with GitHub Actions from `.github/workflows/pages.yml`.

1. In GitHub repository settings, open Pages and set **Source** to **GitHub Actions**.
2. Push to `main` (or run the workflow manually from the Actions tab).
3. The workflow builds with MkDocs and deploys the generated `site/` artifact.

With this setup, you do not need to point Pages to `/docs`, and the root `README.md` is not used as the published site home page.

## Contributing

Source files are the `.md` files in `docs/`. Edit them and rebuild the site using the instructions above.

Deliverables are grouped under the folder-based section `docs/04-Deliverables/`. Add new deliverable files in that folder, summarize them in `docs/04-Deliverables/index.md`, and keep the ordering rules in the local `.pages` files or use indices.
